# 코드 리팩토링 설계서

## 현재 코드 구조 진단

### 문제 1: 네이밍 일관성 부재
- 개발자별 접두어 혼재: `Jaein_`, `Ryeol_`, `fbdfbd_`, `SSH_`, `WS_`
- 같은 개념인데 다른 이름: `fbdfbd_EnemyProjectile` vs `SSH_EnemyProjectile`
- 클래스명에 개발자 이름이 포함 → 협업/유지보수 시 혼란

### 문제 2: 책임 분리 미흡 (SRP 위반)
- `Jaein_BatWeaponManager` (848줄): 차지 + 비주얼 + 공격 실행 + 충돌 + 넉백 + 투사체 반사 전부
- `Jaein_PlayerController` (289줄): 입력 + 이동 + 대시 + 공격 + 투사체 파괴 전부
- `Ryeol_EnemySpawner`: 웨이브 관리 + 스폰 + 적 컨테이너 관리

### 문제 3: 하드코딩 스탯
- 플레이어/무기/적 스탯이 각 MonoBehaviour의 SerializeField에 직접 존재
- 밸런싱할 때 프리팹 하나하나 열어서 수정해야 함
- 중앙 데이터 관리 없음

### 문제 4: 적 투사체 중복
- `fbdfbd_EnemyProjectile`과 `SSH_EnemyProjectile` 거의 동일한 기능
- BatWeaponManager와 PlayerController에서 두 타입을 각각 별도 if문으로 처리
- 새 투사체 타입 추가 시 여러 곳 수정 필요

### 문제 5: 참조 방식 혼재
- 전통적 싱글톤 (GameManager, DamageTextManager)
- `FindObjectOfType` (OrbitalWeapon에서 PlayerController 찾기)
- Inspector 직접 참조
- `GetComponent` / `GetComponentInChildren`
- 일관된 패턴 없이 혼합 사용

### 문제 6: 이벤트 시스템 미통일
- `GameManager`에 `Action` 이벤트 일부 존재
- 대부분은 직접 메서드 호출로 통신
- 중앙 이벤트 버스 없음 → 모듈 간 강한 결합

## Phase 1: 투사체 통합 (가장 쉬움, 먼저 하기)

### 목표
`fbdfbd_EnemyProjectile`과 `SSH_EnemyProjectile`의 중복 제거

### 작업

**Step 1: 인터페이스 생성**

파일: `Assets/01. Scripts/Enemy/IEnemyProjectile.cs` (새 파일)
```csharp
public interface IEnemyProjectile
{
    void ReflectAsBatHit(int damage, LayerMask targetLayer, Color color);
    Rigidbody2D Rb { get; }
}
```

**Step 2: 기존 클래스에 인터페이스 구현**

`fbdfbd_EnemyProjectile.cs`:
```csharp
// 변경 전
public class fbdfbd_EnemyProjectile : MonoBehaviour

// 변경 후
public class fbdfbd_EnemyProjectile : MonoBehaviour, IEnemyProjectile
{
    public Rigidbody2D Rb => GetComponent<Rigidbody2D>();
    // 나머지 기존 코드 유지
}
```

`SSH_EnemyProjectile.cs`도 동일하게 `IEnemyProjectile` 구현

**Step 3: 사용처 수정**

`Jaein_PlayerController.OnTriggerEnter2D()`:
```csharp
// 변경 전 (2개 if문)
if (other.TryGetComponent<fbdfbd_EnemyProjectile>(out _))
    Destroy(other.gameObject);
if (other.TryGetComponent<SSH_EnemyProjectile>(out _))
    Destroy(other.gameObject);

// 변경 후 (1줄)
if (other.TryGetComponent<IEnemyProjectile>(out _))
    Destroy(other.gameObject);
```

`Jaein_BatWeaponManager.OnWeaponTriggerEnter2D()`:
```csharp
// 변경 전 (2개 블록)
fbdfbd_EnemyProjectile projectile = collision.GetComponent<fbdfbd_EnemyProjectile>();
if (projectile != null) { HandleEnemyProjectile(projectile, chargeLevel); return; }
SSH_EnemyProjectile sshProjectile = collision.GetComponent<SSH_EnemyProjectile>();
if (sshProjectile != null) { HandleEnemyProjectile(sshProjectile, chargeLevel); return; }

// 변경 후 (1개 블록)
IEnemyProjectile projectile = collision.GetComponent<IEnemyProjectile>();
if (projectile != null) { HandleEnemyProjectile(projectile, chargeLevel); return; }
```

`HandleEnemyProjectile()`, `PushEnemyProjectile()`, `ReflectEnemyProjectile()`:
- 매개변수 타입을 `Component` → `IEnemyProjectile`로 변경
- `GetComponent<Rigidbody2D>()` → `projectile.Rb`
- `ReflectAsBatHit()` 호출은 인터페이스 메서드로 통일

**Step 2: 기존 클래스 수정**

각 클래스에 SO 참조 추가, 기존 SerializeField는 SO 값으로 대체:

`Jaein_PlayerController.cs`:
```csharp
// 추가
[SerializeField] private PlayerStatsData _statsData;

// Awake에서 SO 값으로 초기화
private void InitFromData()
{
    if (_statsData == null) return;
    _moveSpeed = _statsData.moveSpeed;
    _rotationSpeed = _statsData.rotationSpeed;
    _dashSpeed = _statsData.dashSpeed;
    _dashDuration = _statsData.dashDuration;
    _dashCooldown = _statsData.dashCooldown;
}
```

같은 패턴으로 BatWeaponManager, OrbitalWeapon, EnemyBase에 적용.

**Step 3: SO 에셋 생성**

1. `Assets/Data/` 폴더 생성
2. `Create → Game → PlayerStats` → 값 설정
3. `Create → Game → WeaponStats` → 차지 4레벨 값 설정
4. `Create → Game → OrbitalStats` → 궤도/발사 값 설정
5. 적 프리팹 종류별 `Create → Game → EnemyStats`

**Step 4: 프리팹에 SO 연결**

각 프리팹의 Inspector에서 해당 SO 에셋 할당.

### 장점
- **밸런싱**: SO 하나 수정 → 모든 프리팹에 즉시 반영
- **비교**: SO 에셋을 나란히 열어서 수치 비교 가능
- **실험**: SO 복제 후 수치 변경 → 즉시 테스트, 롤백 쉬움

### 작업 방법

1. **팀 전체 합의** (Merge 충돌 방지)
2. **모든 브랜치 merge 후 진행** (한 브랜치에서만)
3. **IDE Rename Symbol (F2)** 사용 (참조 자동 갱신)
4. **한 파일씩** 변경 → 컴파일 → 다음 파일
5. **파일명도 같이 변경** (Unity Project 창에서 rename)
6. **씬 파일/프리팹의 참조**는 Unity가 GUID로 추적하므로 자동 갱신됨
   - 단, SerializeField의 필드명이 바뀌면 값이 초기화될 수 있으므로 주의
   - 클래스명만 변경하고 필드명은 유지하면 안전

**BatWeaponManager.cs** (리팩토링 후 ~80줄):
```
담당: 파사드(Facade). 3개 시스템 조율.

public class BatWeaponManager : MonoBehaviour
{
    [SerializeField] private WeaponChargeSystem _charge;
    [SerializeField] private WeaponSwingSystem _swing;
    [SerializeField] private WeaponHitProcessor _hit;

    // 외부 인터페이스 유지 (기존 참조 깨지지 않게)
    public bool IsAttacking => _swing.IsAttacking;
    public bool IsCharging => _charge.IsCharging;
    public float ChargePercent => _charge.ChargePercent;

    public void HandleAttackInput(bool pressed, bool held, bool released)
    {
        _charge.HandleInput(pressed, held, released);

        if (released && !_swing.IsAttacking)
        {
            _swing.StartAttack(_charge.ChargePercent, _charge.CurrentChargeLevel);
            _charge.Reset();
        }
    }

    // 외부에서 호출되는 트리거 메서드 유지
    public void OnWeaponTriggerEnter2D(Collider2D col) => _hit.OnTriggerEnter(col);
}
```

### 작업 순서

1. 3개 새 파일 생성 (빈 클래스)
2. `WeaponChargeSystem`에 차지 코드 복사 → 컴파일
3. `WeaponHitProcessor`에 타격 코드 복사 → 컴파일
4. `WeaponSwingSystem`에 스윙 코드 복사 → 컴파일
5. `BatWeaponManager`에서 이동된 코드 삭제, 위임 코드로 교체
6. 프리팹에 3개 컴포넌트 추가 + 참조 연결
7. 플레이 테스트

### 핵심 주의사항
- **외부 참조 유지**: `PlayerController`에서 `_weaponSystem.IsAttacking` 등을 그대로 사용 가능하게
- **프리팹 구조**: 3개 컴포넌트 모두 같은 GameObject(Weapon)에 부착
- **코루틴**: `SwingSystem`이 코루틴 소유, `BatWeaponManager`는 StartCoroutine 위임하지 않음

## Phase 7: 오브젝트 풀링 확대

### 목표
Instantiate/Destroy 남용 → 풀링으로 성능 개선

### 작업

**Step 1: 범용 ObjectPool 생성**

파일: `Assets/01. Scripts/Core/ObjectPool.cs`
```csharp
using System.Collections.Generic;
using UnityEngine;

public class ObjectPool<T> where T : MonoBehaviour
{
    private readonly T _prefab;
    private readonly Transform _parent;
    private readonly Queue<T> _pool = new Queue<T>();

    public ObjectPool(T prefab, Transform parent, int initialSize = 0)
    {
        _prefab = prefab;
        _parent = parent;
        for (int i = 0; i < initialSize; i++)
            _pool.Enqueue(CreateNew());
    }

    public T Get()
    {
        T obj = _pool.Count > 0 ? _pool.Dequeue() : CreateNew();
        obj.gameObject.SetActive(true);
        return obj;
    }

    public void Return(T obj)
    {
        obj.gameObject.SetActive(false);
        _pool.Enqueue(obj);
    }

    private T CreateNew()
    {
        T obj = Object.Instantiate(_prefab, _parent);
        obj.gameObject.SetActive(false);
        return obj;
    }
}
```

**Step 2: 적용 대상 (우선순위순)**

1. **적 투사체** (가장 빈번한 생성/파괴)
   - `EnemyRange`, `EnemyMine`의 Instantiate → pool.Get()
   - 투사체 수명 종료 시 Destroy → pool.Return()

2. **적** (웨이브마다 대량 생성)
   - `WaveManager.SpawnEnemy()` → pool.Get()
   - 적 사망 시 Destroy → pool.Return()
   - 주의: 적 타입별 풀 필요 (Dictionary<GameObject, ObjectPool>)

3. **데미지 텍스트** (기존 WS_DamageTextPool을 범용으로 교체)

### 확인사항
- [ ] 풀에서 꺼낸 오브젝트 초기화 정상 (HP 리셋, 위치 등)
- [ ] Return 시 정리 정상 (코루틴 중단, 이벤트 해제 등)
- [ ] 메모리 사용량 감소 확인 (Profiler)
- [ ] 프레임 드랍 개선 확인
